# PNT-027 — صور الفحص الخاصة (notes)

Private inspection photos as the `media` module (`packages/server/src/modules/media/`): presigned upload to a private
bucket, server-side verification and EXIF/GPS stripping (DEC-36), short-lived signed reads. No dependency on
`tickets-custody`: the module reads `tickets`/`tasks` with SQL.

## Behaviour

**`POST /v1/tickets/{ticketId}/media`** (`ticket.intake`, ✓, 201) — order: CSRF → session → permission → L0 → body
(`VALIDATION_FAILED`, then `MEDIA_TYPE_UNSUPPORTED` with `allowed_types`, then `MEDIA_TOO_LARGE` with `max_bytes` =
`MEDIA_MAX_BYTES`) → ticket in org + venue scope, and for a driver not closed (`TICKET_NOT_FOUND`) → creator
(`PERMISSION_DENIED`) → **L5** ticket lock → re-check → status `received`/`parking` (`INVALID_STATE_TRANSITION`,
`allowed_from`) → extra-photo limit → `media_assets(pending)` with key `incoming/{org}/{ticket}/{media}-{nonce}` →
presigned PUT (`MEDIA_UPLOAD_URL_TTL_S`, signed type and exact length) → `audit_log`. Presigning is the only storage
call and it is local. The ticket version is not changed (07 §3.1 example).

**`POST /v1/media/{mediaId}/complete`** (`ticket.intake`, ✓, 200) — two phases:

1. *Storage phase, before any transaction* (`MediaCompletionPreparer`, a route guard: it runs after the session and
   permission guards and before the `CommandInterceptor` opens the command transaction). Skipped when the
   Idempotency-Key is missing, malformed or already known (the interceptor answers). Checks: uploader + scope
   (`RESOURCE_NOT_FOUND`, `resource: media`), status (`uploaded` → nothing to do; `failed`/`deleted` →
   `MEDIA_UPLOAD_INCOMPLETE`), object exists (`MEDIA_UPLOAD_INCOMPLETE`), size ≤ `MEDIA_MAX_BYTES`
   (`MEDIA_TOO_LARGE`), size = declared and sha256 = declared at request and/or in the body
   (`MEDIA_UPLOAD_INCOMPLETE`), bytes decode as the declared type (`MEDIA_TYPE_UNSUPPORTED`, TC-071), EXIF/GPS
   stripped, sanitized copy written create-only to `org/{org}/tickets/{ticket}/{media}.{ext}` (09 §6.1) with
   `Cache-Control: private, no-store`, **original deleted** (09 §6.2: before `uploaded`). On any rejection the
   original is deleted too and the row stays `pending` (the client may re-PUT while its URL is valid). The guard never
   rejects: it leaves a plan on the request.
2. *Command transaction* (handler): plan error → thrown here, so a deterministic 4xx is stored with the key and a 5xx
   is not; L5 ticket → media row (`FOR NO KEY UPDATE`) → re-check → `uploaded` with the **new size, sha256, key and
   type** → `audit_log` (before/after, original size/hash) → `ticket_events` `ticket.photo_uploaded` → late inspection
   completion.

Safe twice: the same key replays; a new key on an `uploaded` row answers it as is (an audit row with
`result: already_uploaded`, no storage call, no second timeline entry); two concurrent calls converge (create-only
put: the loser adopts the stored bytes, or resumes from them when the original is already gone); a completion whose
transaction failed after the storage phase resumes from the sanitized copy. Storage failures → `504
DEPENDENCY_TIMEOUT` (`dependency: object_storage`, retryable, not stored with the key) or `500` for configuration
errors.

**Late inspection completion (11 §2.4, §6.3)** — in the same transaction, when the ticket is open,
`inspection_status = incomplete`, `submitted_at` set, and every kind of `inspection.required_photos` has an `uploaded`
photo with `COALESCE(captured_at, created_at) <= submitted_at`: `inspection_status = complete`, `version + 1`,
`vehicle_inspections.required_photos_ok = true` for the intake inspection if one exists, `ticket_events` and the canon
domain event `ticket.inspection_completed` (`{ticket: TicketRef, media_id}`). Resolving the `inspection_incomplete`
alert and the WS `ticket.updated` are left to their consumers (planners/projectors, DEC-41/48).

**`GET /v1/media/{mediaId}/url`** (`ticket.read_photos`, 200, `Cache-Control: private, no-store`) — media in org +
venue scope and `canReadTicketPhotos` (owner/admin/supervisor in scope; a driver only as assignee of an open task on
the ticket, or as its creator while `received`/`parking`), else `RESOURCE_NOT_FOUND` (non-disclosure, before any
status is revealed); not `uploaded` → `MEDIA_UPLOAD_INCOMPLETE` (08 §4.14); presigned GET for
`min(MEDIA_READ_URL_TTL_S, 300)` s with `response-cache-control: private, no-store`. The issuance is logged (ids
only, never the URL).

## S3 / MinIO

Docker Hub is rate-limited here, so MinIO was built from source (`go install github.com/minio/minio@latest`, Go 1.24
through proxy.golang.org) and run on `127.0.0.1:9000`. Against it: the opt-in test above passed, and a one-off script
on the compiled packages passed 10/10 checks — presigned PUT accepted with the signed headers and refused (403) with
another type, another length or after expiry; presigned GET with `private, no-store`; anonymous GET/PUT refused (403);
`If-None-Match: *` honoured (`exists`); unreachable endpoint → `timeout`, wrong secret → `misconfigured`; and the full
flow through the compiled API with `S3_ENDPOINT` set (request → browser-style `fetch` PUT → complete → sanitized
object, original deleted → signed GET serves it → link expired after `MEDIA_READ_URL_TTL_S=2`). The Vitest suites use
the in-memory bucket.

**Vitest and the AWS SDK:** `vitest.config.ts` resolves with the `module` condition and starts workers with
`--conditions module`; the AWS SDK's export maps list a bundler-only `module` build (extensionless ESM) first, so Node
cannot load the SDK inside Vitest at all (production `node dist/…` is unaffected). The module therefore loads the SDK
lazily with `createRequire` (importing `@point/server` never loads it). Proposed fix for the lead: drop `'module'` from
the Vitest `conditions` (or inline `@aws-sdk/*`/`@smithy/*`), after which S3 tests can run in-process.

## Spec gaps and follow-ups

- WS `ticket.updated` on `complete` (07) is not published for a plain photo (DEC-PROPOSED-1); resolving the
  `inspection_incomplete` alert on `ticket.inspection_completed` belongs to the alerts consumer.
- Media rows are not linked to `vehicle_inspections` (`inspection_id` stays NULL); linking belongs to submit-intake
  (PNT-028) and the incident/handover inspections (11 §6.3 last line).
- 02 D-06 "a retake replaces the photo of the same kind" is a UI rule: the server keeps every photo (no silent delete);
  the newest per kind is current; superseded ones go with retention.
- `retention.photos_days` purge (`job.retention_purge`: delete object, `upload_status = deleted`, `delete_reason =
  retention`) is not part of this ticket.
- With IAM-role credentials (no static keys) the SDK may refresh credentials over the network during a presign inside
  the request transaction; static keys keep presigning purely local.
- Web: CSP `img-src`/`connect-src` must allow the storage host (05 §14.1); uploads must send the instruction headers
  verbatim and a body of exactly `byte_size` bytes.
- Rate limiting (07 §1.9 `command`/`read`) is not implemented by the core yet.
