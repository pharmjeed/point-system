Deterministic dev/test seed whose content is `docs/17_Test_Acceptance_Plan.md` §4. Code lives in
`packages/db/src/seed/`, the test in `packages/db/test/seed.int.test.ts`.

## Behaviour

- `seed(client: pg.ClientBase | pg.Pool, opts?)` runs in **one transaction** (its own `BEGIN`/`COMMIT`, so do not
  call it inside an open transaction), serialised by `pg_advisory_xact_lock(hashtext('point.db.seed'))`.
- Every row has a fixed id and is written with `INSERT … ON CONFLICT (id) DO NOTHING`: a re-run inserts nothing and
  changes nothing (no `UPDATE`, so no `updated_at` trigger fires). A collision on any *other* unique key (same phone,
  a second active channel, a second open shift, …) raises instead of being skipped.
- argon2 hashing and MFA encryption run only for users that do not exist yet.
- Refused (`SeedRefusedError`) before touching the database when `opts.env ?? APP_ENV` is `production`, `prod` or
  `staging` (case-insensitive) or `opts.nodeEnv ?? NODE_ENV` is `production`; refused inside the transaction when the
  database already holds a `whatsapp_channel` row with `mode = 'live'`.
- Options (all optional): `env`, `nodeEnv`, `dataEncryptionKey`, `dataEncryptionKeyId`, `secretPepper`,
  `customerBrandNameAr`; defaults come from `APP_ENV`, `NODE_ENV`, `DATA_ENCRYPTION_KEY`, `DATA_ENCRYPTION_KEY_ID`,
  `AUTH_SECRET_PEPPER`, `BRAND_CUSTOMER_NAME_AR`. The CLI does not load `.env` itself.
- Returns `SeedSummary { appEnv, tables: { <table>: { inserted, existing } }, dataKeyId, usedDevDataKey, pepperApplied }`.

## Identifiers (`SEED_IDS`)

Format `00000000-0000-4000-8000-KKKKAAAABBBB` (v4 layout; never collides with the `…-0000-0000-…` ids used by
`06_schema_invariants_test.sql`). `KKKK`: `0001` org, `0002` venues, `0003` pools, `0004` users, `0005` role scopes,
`0006` assignments, `0007` events, `0008` shifts, `0009` customers, `000a` zones, `000b` spots (zone index + number),
`000c` key boards, `000d` key slots (board index + number), `000e` channel.

## `mfa_secret_enc` format (for the server)

```
<keyId>:<iv base64>:<tag base64>:<ciphertext base64>
```

AES-256-GCM, key = base64-decoded `DATA_ENCRYPTION_KEY` (exactly 32 bytes), `keyId` = `DATA_ENCRYPTION_KEY_ID`
(`^[A-Za-z0-9_.-]{1,64}$`), IV 12 random bytes, tag 16 bytes, no AAD, standard base64 with padding, plaintext = UTF-8 of
the base32 TOTP secret. Reference implementation: `decryptField(value, Map<keyId, keyBuffer>)` in `src/seed/crypto.ts`.
When `DATA_ENCRYPTION_KEY` is empty (non-production only) the seed uses the published dev-only key
`DEV_DATA_ENCRYPTION_KEY` with id `dev0`; to decrypt seeded MFA secrets locally, configure the server with
`DATA_ENCRYPTION_KEY=J0fYaXmFXs1TdlfW/n9DaIpgvRF/ntOunEAKS7scTFg=` and `DATA_ENCRYPTION_KEY_ID=dev0`, or set your own key
before seeding. Changing the key later does not re-encrypt existing rows (the seed never updates).

## How it was run and tested

```bash
export PATH=/opt/node24/bin:$PATH
npx tsc -p packages/db/tsconfig.build.json                       # builds packages/db/dist/seed/*
psql "$ADMIN_URL" -c 'CREATE DATABASE seed_dev_a7c31e'
psql postgres://…/seed_dev_a7c31e -v ON_ERROR_STOP=1 -f docs/06_schema.sql
DATABASE_URL=postgres://…/seed_dev_a7c31e node packages/db/dist/seed/cli.js   # run 1: all rows inserted (0.3 s)
DATABASE_URL=postgres://…/seed_dev_a7c31e node packages/db/dist/seed/cli.js   # run 2: inserted 0 everywhere
APP_ENV=production … node packages/db/dist/seed/cli.js                           # refused, exit 3
psql postgres://…/seed_dev_a7c31e -v ON_ERROR_STOP=1 -f docs/06_schema_invariants_test.sql   # ALL INVARIANT TESTS PASSED
TEST_DATABASE_URL=postgres://postgres:postgres@localhost:5432/postgres \
  npx vitest run --root . packages/db/test/seed.int.test.ts --project integration       # 16/16 passed
```

The test creates and drops its own databases (`seed_test_*`, `seed_live_*`, `seed_devkey_*`), applies `docs/06_schema.sql`,
and asserts: per-table counts equal 17 §4 (literal numbers, not the seed's constants); exact venues, pools, zones/spot
labels, boards/slot labels, roles, MFA, `can_drive`, scopes, assignments, events, shifts, customers, channel; no
tickets/duty/tasks/templates/audit/outbox rows; argon2id verification of every seeded secret (with pepper, and that the
pepper is really applied); MFA decryption; a second run through a `pg.Pool` changes no row in any table (count + md5 of
every base table); refusal for `production`, `PRODUCTION`, `staging`, `NODE_ENV=production` and from the environment,
without touching the database; refusal on a live channel with nothing written; dev fallback key; brand name from
configuration; malformed key rejected; and `06_schema_invariants_test.sql` passing on the seeded database (every
`expect_fail` rejected). The integration project's `globalSetup` file did not exist in this worktree, so a temporary
stub `packages/server/test/global-setup.ts` (`export default async () => {}`) was used and not committed.
