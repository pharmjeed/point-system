## Proposed decisions

**DEC-51 — Error text precedence.** 08 §1.3 rule 8 says the UI keeps its own text per code and falls back to the
server's `message_ar`; 03 §4.1/§6 and 07 §1.6 say to show `message_ar`; the 02 header says 08 wins when 02 and 08
differ. Adopted: show the server's `message_ar` (which is the 08 text) and fall back to the 08 map in
`apps/web/src/i18n/errors.ts` (generated from 08 §4) when a reply has no envelope. The screen-specific texts in 02 for
server codes — D-01 `AUTH_INVALID_CREDENTIALS` «رقم الجوال أو الرقم السري غير صحيح.», D-02 «الرقم السري الحالي غير
صحيح.» / «اختر رقمًا سريًا أقوى.», S-01 «رقم الجوال أو كلمة المرور غير صحيحة.» — are therefore not shown for server
answers (the D-02 ones are used for the local pre-checks). Fix: align 02 to 08, or give 08 context-specific texts.

**DEC-52 — Front-end routes and the two sign-in screens.** 02 §9.1 is adopted as the router: `/login` (D-01),
`/account/secret` (D-02), `/staff/login` (S-01), `/d/start`, `/d`, `/d/vehicles`, `/d/account`, `/session-ended`,
`/ops`, `/drivers`, `/venues`, `/reports`, `/admin`. Two screens as in 02: D-01 for drivers with a link to S-01; D-01
accepts any account (02 D-01) and hands an MFA account over to S-01 step 2 with the `mfa_token` in memory. The
orchestration brief's `/change-secret` and `/s` are kept as redirects. S-01 steps are one route whose step is derived
from the in-memory `mfa_token` and from `/v1/me` (`user.must_change_secret`, then `session.restricted`).

**DEC-53 — Expired `mfa_token` code.** 07 §1.2 says an expired `mfa_token` returns `401 AUTH_SESSION_EXPIRED`;
07 §2.1, `07_openapi.yaml`, 08 §4.1 and PNT-012 say `401 AUTH_MFA_REQUIRED`. The UI treats both as "start again from
the password" with the server text. Fix 07 §1.2 to `AUTH_MFA_REQUIRED`.

**DEC-54 — `Me` should state the pending restriction.** `Me.session.restricted` does not say whether a secret change
or an MFA setup is pending; the UI derives it (`must_change_secret` first, otherwise MFA setup) and keeps the
`LoginResult` flags. Propose `Me.session.pending: ('secret_change' | 'mfa_setup')[]` in 07.

**DEC-55 — Brand names in the web build.** 05 §8 lists `VITE_BRAND_STAFF_NAME_AR/EN` only; the customer name is
needed on the allowed surfaces (D-07, S-03, S-13): add `VITE_BRAND_CUSTOMER_NAME_AR`. The single `.env` is read from
the repo root (`envDir`). When `VITE_BRAND_STAFF_NAME_AR` is not set at all (fresh clone, CI), `vite.config.ts` takes
the manifest's `short_name` (the brand asset) instead of a literal; `/v1/me` `brand` (org settings) overrides at
runtime. `index.html` uses `%VITE_BRAND_STAFF_NAME_AR%` for the title and the iOS app title.

**DEC-56 — Component folder.** 03 §3/§8 suggest `apps/web/src/ui/`; the PNT-021 brief asked for
`apps/web/src/components/`. Used `src/components/` (names exactly as 03 §3). Update 03 §8.

**DEC-57 — Direction of forward chevrons.** The design system mirrors `chevron-left` under RTL, so `ListItem` points
to the inline start (screenshot shows ›). 03 §2.6 intends mirrored LTR icons: the app authors the LTR "forward" icon
(`chevron-right`) and mirrors it, so the chevron points to the inline end (‹) as in Arabic platform lists; "back"
arrows point to the inline start. Record as a design-system correction.

**DEC-58 — Automatic retry of a command.** 02 §1.8 item 3: one automatic retry after 2 s; 08 §3/§8.2: up to three with
1 s, 3 s, 7 s. Adopted 08 (same key and body each time; `IDEMPOTENCY_IN_PROGRESS` waits `Retry-After` or 2 s;
`INTERNAL_ERROR` once; `RATE_LIMITED` and business errors are never retried automatically). Fix 02 §1.8.

**DEC-59 — Toast duration.** 03 §3.14: 4 s; 02 §1.6: success toasts 3 s. Adopted: success 3 s, others 4 s.

**DEC-60 — Session expiry for drivers.** 02 §1.6 sends an ended session to D-15 (c); 02 §1.9 says
`AUTH_SESSION_EXPIRED` goes to the sign-in screen. Adopted: `AUTH_SESSION_EXPIRED`/`REVOKED` → D-15 (c) with the
reason text (D-15 has an "expiry" reason); `AUTH_UNAUTHENTICATED` (no session at all) → D-01 with
«انتهت الجلسة. سجّل الدخول للمتابعة.». Staff always return to S-01 with the reason line.

**DEC-61 — Copy the UI needed that 02 does not define** (all in `apps/web/src/i18n/ar.ts`, to be confirmed in 02 §8):
placeholder screens «قيد الإنشاء» / «تُبنى هذه الشاشة في مرحلة لاحقة من الخطة.»; reveal toggle «إخفاء» (02 has only
«إظهار»); S-01 → D-01 link «دخول السائقين»; S-01 step 3 title «تغيير كلمة المرور»; «كلمتا المرور غير متطابقتين.»;
the TOTP field label «رمز التحقق»; manual MFA key «أو أدخل هذا المفتاح يدويًا في التطبيق:»; the ☰ label «القائمة»;
the lock countdown «يمكنك المحاولة بعد {time}» (08 asks for a countdown); banner action «تفعيل الصوت» (design system);
«الصفحة غير موجودة.». A new PIN that is not six digits shows the D-02 intro sentence; a short staff password shows the
S-01 hint «استخدم كلمة مرور طويلة يصعب تخمينها.».

**DEC-62 — Driver state wording.** 02 §8.1 «مشغول + مهمة تالية» vs design system «مشغول ولديه مهمة تالية»: 02 owns
staff copy, §8.1 used.

**DEC-63 — Vehicle colour swatches missing from the design system.** 02 §8.4 has `navy`, `yellow`, `orange`; the
design system's `VEHICLE_COLORS` does not. Primitives used (DEC-49d exception): navy `--pt-blue-900`, yellow
`--pt-amber-400`, orange `--pt-orange-400`.

**DEC-64 — Connection indicator before realtime.** Until PNT-064/065 the indicator shows `online`/`offline` from
`navigator.onLine`, and «آخر مزامنة» from the server time of the last successful reply; `uncertain` comes with
heartbeats (`heartbeat.uncertain_after_s`).

**DEC-65 — D-01 secret field.** No `maxLength` on the secret (a staff password may be typed on D-01, which 02 allows);
numeric keypad hint only; length is the server's rule (`VALIDATION_FAILED`). Arabic-Indic digits are normalised in
every numeric field.

**DEC-66 — CSP.** 09 §9.3 asks for a strict CSP. No `<meta>` CSP in `index.html` (Vite dev injects inline scripts);
the built app has no inline script, so the header belongs to the server/infra (`script-src 'self'`, `img-src 'self'
data:` for inlined SVG assets, `connect-src 'self'`).
