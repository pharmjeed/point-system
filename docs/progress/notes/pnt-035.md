## How the screens work

- **Sync.** `GET /v1/me/home` is polled every 5 s on D-04 and read by the task screens (one cache entry); each
  command reply is written into the cache at once, then the snapshot is re-read. Realtime replaces the polling in
  PNT-065. The reserved next task becoming current is detected between snapshots (or returned by `complete-parking`
  / `handover`) and announced with «بدأت مهمتك التالية: #n» → «الانتقال».
- **D-03.** The `AudioContext` is created inside the tap, the test tone plays, then «هل سمعت النغمة؟»; a context
  that cannot resume is «محجوب». The result and the notification permission are recorded on the session's device
  (proposal A). Wake lock support is shown. A closed shift shows the 02 state with «تحديث»; a start refused with
  `SHIFT_NOT_OPEN` re-reads the home so the screen follows the server.
- **Intake (D-05/D-06).** Step 1 (`PATCH …/intake`: channel `paper`, plate, vehicle, stub number) is saved on «التالي»;
  without a reply the step moves on and D-06 resends the same body with the same key (shared `CommandSession`) under
  the banner «لم تُحفظ الخطوة الأولى…». Photos: decoded and re-encoded on the device (longest edge 1600 px, JPEG 0.8 —
  EXIF dropped), `POST …/media` with kind, type, exact byte size, sha256 and capture time, XHR PUT to the returned URL
  with the returned headers (progress), then `POST /v1/media/{id}/complete`; one automatic retry of the PUT and one
  re-PUT on `MEDIA_UPLOAD_INCOMPLETE`; `MEDIA_TOO_LARGE` → 1280 px / 0.7 once. Submit sends the key tag and notes, then
  `submit-intake`; `INSPECTION_INCOMPLETE` asks to continue with the acknowledgement (DEC-31).
- **D-08.** Zones as single-select chips with free counts, the spot grid, «بدون موقف محدد» + a description by
  `parking.mode`, the key board and slot grid by `keys.require_slot`, «أودعت المفتاح» as a local check; an occupancy
  error clears the choice and re-reads the grid.
- **D-10 / D-11.** One button per step (key pickup → start → ready → handover); key slot, spot, damage notes and the
  photos through ≤300 s signed URLs (memory only). D-11 takes the stub number (the code is PNT-047) and the collection
  of a per-vehicle event in the same `handover` call (13); `PAYMENT_ALREADY_RECORDED` syncs and resends without the
  payment (02 D-11).
- **Storage.** Drafts, photos (object URLs), the last event chosen and the audio state live in memory only
  (`intakeStore.ts`, `stores/field.ts`) and are cleared on logout and session end; nothing driver-side is written to
  browser storage. The IndexedDB queue across reloads is PNT-071.

## E2E fake and the live-API mode (PNT-036)

`e2e/support/fake/routesDriver.ts` adds the driver routes to the PNT-023 fake: home, duty, device checks, intake,
photos with a fake presigned storage (`/__e2e_storage/:mediaId`, public, Content-Type checked like a signature),
parking, a small dispatch engine (oldest request first, single offer to the longest-idle available driver, broadcast
when nobody is free, lazy expiry with `accept_grace_ms`, first accept wins, one reserved next task, promotion on
completion, an intake withdrawing the driver's live single offer as in 10 §7.1), the retrieval steps and handover
with payment. Successful commands append custody events and audit rows. A refused command changes nothing.

`e2e/support/backend.ts` is the seam for PNT-036: `E2E_BACKEND=live` runs against the real API seeded with
`pnpm db:seed` behind `vite preview`'s proxy (`vite.config.ts` now targets `localhost:API_PORT`); `liveSignIn` signs a
context in with the development seed credentials (+ TOTP for OWN1/ADM1, `e2e/support/totp.ts`), `liveExec` is the
counterpart of `fake.exec` (CSRF header, fresh UUIDv4 key), `fakeOnly()` skips the specs that inject faults or read
the fake's world. The G1 scenario then needs only its assertions on `fake.world` turned into API reads.

## Proposed decisions (numbering left to the lead)

**A — `Me.session.device_id`.** `POST /v1/me/audio-test` requires `device_id` and `PUT /v1/me/devices/{deviceId}`
needs the id, but `GET /v1/me` does not say which `devices` row the sign-in linked (09 §9.5, `auth_sessions.device_id`).
Proposed: `Me.session.device_id`. The app uses it when present; without it D-03 keeps the checks on the device only.

**B — `DriverHome.settings`.** D-06 (`inspection.required_photos`, `max_extra_photos`), D-08 (`parking.mode`,
`keys.require_slot`) and the D-09 ring (`dispatch.single_offer_ttl_s`) need venue settings a driver cannot read.
Proposed: a `settings` snapshot of those keys in `GET /v1/me/home`; the app falls back to the canon §12 defaults.

**C — `DriverHome.shift`.** D-03 shows «الوردية: مفتوحة منذ 6:30 م»; `DriverHome` has `shift_open` only. Proposed:
`shift {id, status, opened_at}`; without it D-03 shows «الوردية: مفتوحة».

**D — `TaskCard.ready_at`.** The D-04 row «بانتظار العميل · منذ {مدة}» counts from readiness; `TaskCard` has no ready
time, so the app uses `claim_code.issued_at` (WhatsApp) or `requested_at` (paper). Proposed: `ready_at` (the cycle's).

**E — Plate letters.** The pad shows «هـ» (03 §3.7) and 07 §1.8 writes «ه» on the wire: the app maps both ways. A
non-Saudi plate («لوحة أخرى») has no country field in 02 D-05 while `plate.country` is required: the app sends the
ISO user-assigned code `XX` with `raw`. Proposed: name that value in 07 (or add a country picker to D-05).

**F — Make and colour on the wire.** Sent as the 02 §8.4 keys (`toyota`, `white`; 02 §9.3 item 16) and translated in
the UI; «أخرى» sends the typed text. 07's examples show Arabic values («تويوتا»): proposed to align the examples.

**G — Error wording: 02 per-screen texts vs 08.** Several 02 error tables word the text differently from 08
(D-06 `KEY_TAG_IN_USE` with the conflicting number, D-08 `PARKING_SPOT_OCCUPIED` with the spot, D-10
`CUSTODY_HOLDER_MISMATCH`, D-11 `PAPER_STUB_MISMATCH`). Following DEC-80 the screens show the server's `message_ar`
(the 08 text); the 02 state texts that are not error replies are kept (D-03 «لا توجد وردية مفتوحة في {الموقع} الآن…»
with «تحديث» next to the 08 text under the button). Proposed: align the 02 tables with 08, or let `message_ar` carry
the specifics (08 `details` already has `conflicting_display_number`, `parking_spot_id`).

**H — `CUSTODY_HOLDER_MISMATCH` on D-10.** 08 says refetch + a dialog «راجع المشرف»: the dialog's title is the server
text and its single button «فهمت»; the step stays available. Proposed: a dialog body text in 02 D-10 if wanted.

**I — The reserved next task.** 02 D-04 names the badge «محجوزة لك» where the design system's `TaskCard` shows
«تالية»: `TaskCard` gained a `badge` prop and D-04 passes the 02 text; the line is «منذ {مدة}» since the request
(`components.time.sinceMinutes`) and «تبدأ بعد إنهاء مهمتك الحالية…». Proposed: the design system takes the 02 text.

**J — D-03 dialogs.** «هل سمعت النغمة؟» confirms with «نعم، سمعتها» and cancels with «لا». The untested-audio dialog
answers its question «هل تريد البدء الآن؟»: «البدء دون اختبار» is the confirm button and «اختبار الصوت الآن» the
other (02 lists them the other way round, without saying which is primary). Escape closes either dialog without an
answer (nothing recorded, nothing started).

**K — Copy not in 02** (in `ar.ts`, listed in `test/copy.test.ts`): D-05 «اسم الشركة» and «وصف اللون», the labels of the
«أخرى» free-text inputs. Brand names in 02 texts («أبقِ بوينت مفتوحًا…») are the `{brand}` placeholder filled from
`VITE_BRAND_STAFF_NAME_AR` (canon §1).

**L — Required intake fields.** Local checks follow 08 `INTAKE_INCOMPLETE`: plate, make, colour and the stub number
on D-05, the key tag on D-06; the model is optional. A server `missing` list sends the driver to the step holding the
first field (02 D-06).

**M — D-04/D-03 routing.** Which of the two screens shows is decided by `GET /v1/me` (`duty_session`), not by the
home snapshot, so a stale snapshot cannot bounce between them; D-04 re-reads `/v1/me` when the home shows no duty.

**N — Design-system additions.** `Banner` kind `warning` (D-06 incomplete inspection, D-08 early request) on the
semantic warning pair; `Header`, `Dialog`, `EmptyState` and `Toast` accept rich titles so «#125» is isolated
left-to-right inside Arabic text (`withTicket`; plain strings rendered «125#»); `TaskCard` `badge`; `Dialog`
`onDismiss` (Escape when the second button is an action). Proposed as design-system variants.
